# Deployment Guide — Mess Manager (Django API on Render + Supabase, Android APK)

Goal: other people install the Android APK and use a hosted HTTPS backend.
Stack: Render (free web service) + Supabase (free Postgres) + Expo EAS (APK build).
No Play Store release. Replace `YOUR-SERVICE` with your real Render service name.

## 1. Database — Supabase (free)

1. Create a project at supabase.com (pick a region close to your Render region, e.g. Singapore).
2. Set a database password. Prefer letters+digits; if it has `@ # / : ? &`, URL-encode it in the connection string.
3. Open **Connect** and copy the **Session pooler** string (port **5432**):
   `postgresql://postgres.<project-ref>:<PASSWORD>@aws-0-<region>.pooler.supabase.com:5432/postgres`
   - Do NOT use the "Direct connection": on the free plan it is IPv6-only and Render cannot reach it.
   - Do NOT use the Transaction pooler (port 6543) for Django.

## 2. Backend — Render (free web service)

1. Push the project to GitHub (never commit `.env` files; `.gitignore` already excludes them).
2. Render dashboard -> **New -> Blueprint** -> select the repo. Render reads `render.yaml`.
3. Fill the prompted environment variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | the Supabase **Session pooler** string from step 1 |
| `SUPERUSER_MOBILE` | mobile number of the first Super Manager |
| `SUPERUSER_NAME` | display name |
| `SUPERUSER_PASSWORD` | a strong password (created automatically on first deploy, only if the user does not exist) |

   `SECRET_KEY` is generated by Render. `ALLOWED_HOSTS` / CSRF origin are added automatically
   from Render's hostname. Build runs `build.sh` (install, collectstatic, migrate, ensure_superuser).
4. Wait for the deploy to finish, then verify:
   - [ ] `https://YOUR-SERVICE.onrender.com/healthz/` returns `{"status":"ok"}` (this also proves the DB connection)
   - [ ] `https://YOUR-SERVICE.onrender.com/admin/` login works with the Super Manager mobile + password
   - [ ] `https://YOUR-SERVICE.onrender.com/api/` answers over HTTPS

## 3. Known limits of the free setup (decide before sharing widely)

- **Render sleeps:** a free web service spins down after 15 minutes without traffic and takes about
  1 minute to wake. The app timeout is 15 s (`mobile-app/src/api/client.ts`), so the first call can fail;
  users press **Retry**. Raise `timeout` to `45000` if this is annoying.
- **Supabase pauses:** a free project is paused after about a week of low activity; the API then fails until
  you press *Resume project* in the Supabase dashboard (data is kept; paused projects can be restored for 90 days).
  Opening the Supabase dashboard or real usage counts as activity. An external pinger (e.g. cron-job.org)
  calling `/healthz/` every ~10 minutes keeps Render awake and touches the DB, but Supabase does not
  guarantee that a trivial `SELECT 1` counts as enough activity — check the dashboard weekly for a demo.
- **Instance hours:** Render free gives 750 hours/month per workspace, enough for one always-on service.
- **Receipt images:** media files are served only when `DEBUG=True` and local disk is temporary on free hosts,
  so uploaded receipts will not be viewable on the hosted demo. Real fix: object storage
  (Cloudinary / S3 via `django-storages`). Skipped for now by choice.
- **Rate limits:** anon 100/hour, user 1000/hour, login 10/minute. Many people behind one public IP
  (e.g. a hostel Wi-Fi) share the anon/login limit.
- **Sessions:** access token 12 h, refresh token 7 days. After 7 days users log in again.
- Check current limits on Render's and Supabase's pricing pages; free tiers change often.

## 4. Build the APK (Expo EAS)

1. Create a free Expo account, then `npm install -g eas-cli` and `eas login`.
2. In `mobile-app/eas.json` set `EXPO_PUBLIC_API_BASE_URL` to `https://YOUR-SERVICE.onrender.com/api`
   (HTTPS, so no cleartext-traffic setting is needed). Only the URL goes here — never put secrets in
   `EXPO_PUBLIC_*` variables, they are readable inside the app.
3. `cd mobile-app && eas build --platform android --profile preview`
4. Open the build link on the phone, download the APK, allow "install unknown apps", install.

## 5. Pre-demo smoke test (installed APK, mobile data)

- [ ] Register -> Pending approval -> Super Manager approves -> Login
- [ ] Close and reopen the app: still logged in
- [ ] Meals toggle, Deposit claim, Complaint, Bills view
- [ ] Manager: approve deposit, add expense (receipt photo will not display, see limits), generate bill
- [ ] Member cannot open Expenses / Operations
- [ ] Airplane mode: friendly error with **Retry**, no crash; Retry works after reconnecting
- [ ] Wake-up test: wait 20 minutes, open the app, first call may fail, Retry succeeds
- [ ] Form screens: keyboard does not hide the field being typed in

## 6. Before sharing the link

- [ ] Remove test accounts / test data, or tell testers it is a demo database
- [ ] Do not commit real `.env` files, `SECRET_KEY`, or the database password
- [ ] Tell testers: Android only, personal/demo build
